# Exact binding/reset observation contract

The console launcher compares every result of the frozen generation-32 policy
header with the new diagnostic header against the same owned offscreen-window
sequence. It retains generation-32 eligibility and lifetime behavior, including
ambiguity refusal. This test does not adopt the unintegrated lifetime prototype.

Real controls cover a visible peer, hidden bound window, removed/restored token,
different HWND and expected thread. A wrapper around the real EnumWindows API
injects one enumeration-error case only in this fixture. The exact production
logger and initialized-reset prefix are extracted from pinned production files.
Tests verify log fields, reason coalescing, GetLastError preservation, a throwing
logger and independent exhausted 24-attempt binding/reset budgets. The baseline
and diagnostic executables must produce identical 118 binding decisions.

The separate source-cache launcher exercises the five-file diagnostic tail over
the full 26-file source vector, including every interrupted publication boundary
and unknown edit/file/patch refusal. Historical generation-31 and generation-32
text gates reconstruct their frozen inputs in isolated scratch through the
shared helper, without reversing the live production cache.

No console test launches a game, shows a window on screen, injects a target or
sends input. Actual high-PAGER failure reproduction belongs to the root-owned
packaged app run with matching native and read-only inventory logs.
